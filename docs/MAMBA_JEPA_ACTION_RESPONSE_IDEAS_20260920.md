# Mamba、JEPA 与物理动作响应：原文梳理和实验思路

日期：2026-09-20。用途：供主窗口讨论研究路线。本文来自侧窗口的文献分析，不代表已经实施或验证的项目改动；未修改模型、实验配置或 Git 状态。

## 1. 核心判断

Mamba/SSM 与 JEPA 有结合价值，但应把三个问题分开：

1. **SSM/GRU/Mamba 是状态推进的实现方式**：负责记忆历史和递推未来。
2. **JEPA 是潜在表示预测的训练方式**：帮助编码器保留未来演化需要的信息，可能改善长期 rollout。
3. **物理动作通路是响应约束的来源**：负责阀门作用的方向、延迟、增益和工况依赖。

JEPA 本身不保证“开大阀门必然降温”，也不解决闭环数据中阀门与温度的混杂。值得验证的组合是：**温度监督保证任务精度，多步潜在预测改善状态表示，结构化动作通路保证指定条件下的响应方向。**

建议保持现有骨干，先比较有无潜在预测及其训练方式，再讨论是否换成 Mamba。当前项目的自定义 SSM 不能直接等同于 Mamba。

## 2. 原始资料与实际做法

### 2.1 文本 Mamba + JEPA：存在实现，但收益尚未被独立消融确认

原始实现：[To Jepa Or Not To Jepa: That is Le Question](https://github.com/openai/parameter-golf/blob/main/records/track_non_record_16mb/2026-03-26_37M_LeWM_Jepa_Mamba2_10L_UNet_INT4FP8QAT_Brotli/README.md)。这是仓库中的贡献记录，不等于 OpenAI 研究论文或官方结论。

- Mamba-2 骨干和 U-Net 跳连，主任务仍是文本 token 的交叉熵。
- 隐藏表示经过投影器得到潜在状态，MLP 递归预测后续三个位置的潜在表示。
- 加入 SIGReg 防止表示塌缩；不使用 EMA 目标编码器，也不停止目标分支梯度。
- 辅助预测头在推理时移除。

作者明确将“JEPA 是否改善结果”列为未解决问题，需要关闭 JEPA 权重的消融。它支持“可以这样组合”，不支持“已经证明改善长期物理动力学”。文本实现没有控制动作条件。

原描述提及的“地震 JEPA + SSM”工作，本次未定位到可靠对应原文，不纳入结论。

### 2.2 LeWorldModel：可落地的动作条件 JEPA 配方

论文：[LeWorldModel: Stable End-to-End Joint-Embedding Predictive Architecture from Pixels](https://arxiv.org/html/2603.19312v2)。[作者代码](https://github.com/lucas-maes/le-wm)。

实际做法：视觉编码器得到潜在状态，因果 Transformer 预测下一步表示，动作通过 AdaLN 注入预测器。训练采用一步潜在预测误差与 SIGReg；目标和上下文编码器共同训练，无 EMA、无停止梯度。规划时用预测的终点表示与目标表示计算距离，通过 CEM 搜索动作序列，并在 MPC 中反复更新。

这里 CEM 是 **Cross-Entropy Method，交叉熵优化方法**，不是给阀门和温度添加分类交叉熵损失。SIGReg 主要处理表示塌缩，不提供动作单调性保证。

可以借鉴其简洁的联合训练配方，以及“预测器直接服务于动作搜索”的接口。

### 2.3 Semigroup-JEPA：最值得借鉴的是多步自由递推

论文：[Semigroup-JEPA: Latent Dynamics Consistency for Zero-Shot Physics Generalization](https://arxiv.org/html/2609.10464v1)。[项目页](https://sg-jepa.github.io/)。

论文比较 Transformer、GRU 和 SSM 预测器，并将动作、重力参数作为条件。关键做法是从编码历史出发，将自己预测的潜在状态反馈到后续步骤，训练多步误差，而不是每一步都换成真实编码状态。其配置包括历史长度 20、预测步数 5、折扣因子 0.95，配合 SIGReg。

所谓半群一致性主要来自共享更新函数的反复组合，不应理解为额外加入了一个万能物理约束。有动作时应讨论动作序列下的受控组合；有历史缓存时，完整状态还包括缓存。

结果中 GRU 与 SSM 各有优势；冻结编码器再更换预测器的实验支持“表示学习本身贡献了收益”。因此不能将改进全部归因于 Mamba。论文部分控制实验使用冻结表示上的 Diffusion Policy，不能把所有控制结果都解释为世界模型规划成功。

### 2.4 Akasha 2：可提取结构想法，不能依赖其性能结论

论文状态：[arXiv 2601.06212](https://arxiv.org/abs/2601.06212)。[初版方法](https://arxiv.org/html/2601.06212v1)。

该文已撤回，页面说明：**“No supporting claims were validated in this automated agentic R&D research run”**。因此不以其速度、预测质量或守恒效果作为证据。

初版提出将隐藏状态解释为位置和动量，用学习的势能、专家混合及 leapfrog 积分组织状态演化。可借鉴的抽象想法是“让状态推进遵守结构先验”。但辛积分一般不严格守恒原始哈密顿量；其长时间近似能量保持有条件，参见 [Hairer 关于几何数值积分的说明](https://www.unige.ch/~hairer/preprints/icnaam09.html)。

热工过程存在供热、流动换热和耗散，更适合考虑能量收支或受控耗散系统。相关原文：[Port-Hamiltonian Neural Networks for Learning Explicit Time-Dependent Dynamical Systems](https://arxiv.org/abs/2107.08024)。即便采用这类结构，仍需要额外分析阀门到温度的作用方向。

### 2.5 概率 JEPA 与 HMM：有条件的对应，不是自动等价

论文：[Your Probabilistic JEPA Is Secretly a Hidden Markov Model: A State-Space Interpretation of Joint-Embedding Predictive Learning](https://arxiv.org/html/2608.13621v1)。

文章把概率上下文编码器、潜在预测器和发射方向分别对应到滤波、状态转移与观测生成，并区分计算角色、完整状态空间表示、序列模型等价、训练目标等价四个层次。较强结论需要额外的 Markov 性、分布一致性及目标函数条件。普通确定性潜在 MSE 不自动等于 HMM 最大似然训练。

对项目实用的启发是诊断状态是否遗漏历史：在相同条件下，比较仅用当前状态与额外加入更早历史预测残差的能力。若后者在留出数据上明显更好，提示状态或预测器仍不充分；没有提升也不能证明状态已经充分。论文以小型合成诊断为主，不提供热工任务上的直接性能依据。

## 3. 对原始论述的修正

| 原始说法 | 更准确的理解 |
|---|---|
| JEPA 是隐式双向信息混合器 | 未来目标提供训练监督；推理时过去状态不会因此直接访问未来。 |
| JEPA 让相邻状态靠近、平滑 | 预测误差要求可预测，不要求相邻状态距离小。可预测的突变仍然允许存在。 |
| 标准 Mamba 只优化交叉熵 | 交叉熵来自文本任务，Mamba 骨干也可用回归或其他训练目标。 |
| JEPA 解决动作响应 | 编码器和预测器可能依旧忽略动作，或复制闭环相关性。 |
| SSM 与概率 JEPA 数学上同构 | 都可采用状态递推形式；这不足以证明概率模型、隐状态含义和训练目标等价。 |
| 物理守恒能自动消除漂移 | 结构先验可能限制漂移，但仍受模型误差、外力、耗散和数值积分影响。 |

例如 `z(t+1) = -z(t)` 完全可预测，却不要求相邻表示接近。因此实验应测多步预测能力和动作信息保留，而不是仅看潜在曲线是否光滑。

## 4. 与现有热工模型如何结合：以下为研究提案

### 4.1 最小改动结构

```text
历史温度、阀位、燃烧和其他已知信息
                 │
                 ▼
          编码器 E → 当前状态 z₀
                 │
       候选动作 u、已知外生条件 d
                 │
                 ▼
       共享状态推进 F，连续递推 K 步
                 │
          ┌──────┴──────┐
          ▼             ▼
       温度读出 D     对齐未来编码状态
          │             │
       温度监督       潜在预测监督
```

初版损失可写成：

`L = L_temperature + λ_latent · Σₖ wₖ distance(ẑₜ₊ₖ, E(historyₜ₊ₖ)) + λ_reg · L_anticollapse`

注意：这里未来历史只构造训练目标，不能进入当前状态或预测输入。多步推进必须使用自身预测状态，否则不能验证自由 rollout 的改进。历史窗口高度重叠可能让目标过于容易，需要检验远期效果。

### 4.2 物理动作响应独立设计

可保留“参考预测 + 动作差分响应”的组织方式：

`T̂(u) = T̂_reference + ΔT_physical(u, u_reference; context)`

若同一历史和外生条件下，动作通路使用单调阀门映射、非负因果核和正增益，并且比较不同候选动作时参数保持一致，则能构造指定作用方向的响应。延迟、饱和和不同时间尺度也可显式表达。

这些保证依赖完整计算路径：若候选动作同时改变参考分支、增益、隐藏工况或重编码状态，需要重新检查整体单调性。局部响应头单调不意味着长时间闭环输出仍然单调。

JEPA 可用于改善参考状态及多步演化，但不能直接把包含未来动作影响的编码目标称为“纯背景状态”。当前方向约束也不等于真实作用幅值已经从数据中辨识出来。

### 4.3 三种结合深度

| 路线 | 做法 | 希望解决的问题 | 主要风险 |
|---|---|---|---|
| 轻量辅助 | 现有模型附加潜在预测头 | 改善记忆、减少长期误差 | 潜在任务与温度任务冲突 |
| 联合世界模型 | 状态自由递推，温度是状态读出 | 预测直接支持动作序列规划 | 长期状态漂移，动作被忽略 |
| 结构化动力学 | 状态区分储热、耗散、动作响应等通路 | 结构可解释、方向与稳定性约束 | 分解不唯一，先验错误限制精度 |

优先验证第一条，再依据结果决定是否加深结构。

## 5. 建议的最小消融

保持同一批 1/3 数据、时间切分、训练预算规则和评估协议；不能因加入 JEPA 就减少原有基线覆盖。以下作为新增对照，不替代全部基线结果。

| 编号 | 改动 | 回答的问题 |
|---|---|---|
| J0 | 原模型，仅温度监督 | 基准精度与响应 |
| J1 | J0 + 一步潜在预测 + 防塌缩 | 辅助表示学习是否有效 |
| J2 | J1 改为多步自由潜在递推 | 多步训练是否改善长期演化 |
| P0 | 已有物理响应结构，温度监督 | 物理通路自身的效果 |
| P2 | P0 + J2 训练方式 | 表示学习与响应结构是否互补 |

J0/J1/J2 使用同一骨干；P0/P2 使用同一物理结构。先在一个骨干上完成低成本验证，再对 GRU/SSM 做复核。需要足够训练和早停观察，不能把收敛速度差异误判为方法差异。初筛保留同种子配对对比，候选方案再补种子。

必要时增加一个匹配步数的温度多步训练对照，用来区分“JEPA 的贡献”与“仅仅多做了 rollout 训练”的贡献。

## 6. 怎么判断是否真的进步

### 精度

- 多步 MAE、分块 rollout MAE、原生连续 rollout MAE 分别报告。
- 外推 MAE 按负荷、工况或动作覆盖范围划分，避免混成一个数字。
- 用原始温度单位评价；潜在误差下降不替代温度精度。
- 预先定义可接受的精度非劣阈值，再结合配对误差和重复训练的不确定性判断，不能宣称理论上保证精度不损失。

### 动作响应

- 连续斜坡、正负阶跃、短脉冲、保持后撤回、组合动作。
- 动作分别从窗口前部、中部、后部发生；用距动作起点的时间对齐响应，避免把后期动作的短观察期算成响应弱。
- 检查方向、幅值、延迟、峰值时间、恢复过程、饱和性及跨幅度排序。
- 固定同一历史和外生条件比较候选动作；区分开环响应与控制器反馈产生的闭环响应。
- 动作置零或打乱仅作为依赖性诊断，不能单独证明因果辨识。对分布外动作，合理形状也不代表真实幅值正确。

### 状态与规划

- 编码状态是否塌缩、动作改变后预测状态是否随之改变。
- 更早历史能否进一步解释留出集残差，帮助定位状态信息不足。
- 模型是否对延迟动作、脉冲撤回保留记忆。
- 规划器是否利用异常高增益或不合理快速响应获得虚假的好结果。
- 只有具备可信模拟器或实际反馈时，才能直接评价计划执行效果；模型内目标改善只是中间指标。

## 7. 主窗口讨论的建议顺序

1. 对齐当前充分训练的基线结果，确认精度和响应各自的瓶颈。
2. 选一个现有骨干，完成 J0/J1/J2，优先回答多步潜在训练是否有用。
3. 在同一物理响应结构上比较 P0/P2，判断能否同时保留精度与响应。
4. 若状态仍明显遗漏历史，再考虑更强编码器或 Mamba；若方向正确但幅值过弱，优先检查动作辨识、增益设计与训练冲突。

这条路线的可验证假设是：**多步潜在监督能改善预测器的状态记忆，而受约束的动作通路能将这种记忆转化为更可靠的动作序列模拟。两者是否互补，需要消融确认。**
