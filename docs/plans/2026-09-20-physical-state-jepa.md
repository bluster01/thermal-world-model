# Physical-state JEPA experiment implementation plan

Goal: 在同一1/3数据上比较最小热状态模型P0、EMA未来状态监督P1、双视图交叉未来状态监督P2，区分物理结构与状态预测辅助训练的收益。

Architecture: 五个蒸汽温度状态＋三个受热段金属温度状态；正的有效热容量、换热系数与单调阀门流量映射；隐式Euler推进常比热近似下的质量/热收支。历史网络只初始化金属状态并估计有界外部热输入倍率，不能直接修正温度输出。JEPA式目标对齐有物理坐标的未来估计状态，不把未来未测状态称为真值。

Tech stack: 现有PyTorch/NumPy实验脚手架，复用全套预测及动作评价，不引入新框架。

## 回传决定

focused33四臂均达到预设停滞。short模型A/B/C/D的H32为0.5764/0.5172/0.5966/0.5425；block H512为1.6987/1.4747/1.6717/1.5740。新增信息有益，但D对B仍有精度代价；冻结R4不提供新的幅度辨识。保留这些checkpoint，不重复训练四臂。

## 明确近似与对照

- 首轮是常有效比热的集中参数热网络，不是IAPWS蒸汽焓模型，也不宣称真实金属储热或各级喷水量已辨识。
- steam_flow暂作入口流量代理，feedwater_temperature作冷却水温代理。各级水量由阀位单调映射生成，不能读取真实未来喷水量。
- 热输入随已知燃料边界与起点历史倍率变化；不同候选共享外部热输入。实际换热随候选热状态变化，这是物理反馈，不是另造扰动。
- 完整物理耦合不自动保证所有工况全时域单调；用现有方向/路径/幅度评价揭示代价，不把能量收支当成单调证明。
- P0/P1/P2全部H128自由递推温度监督，相同初始化、数据和停止规则。P0就是匹配递推长度的温度监督对照。
- P1对齐EMA历史状态估计器；P2用完整历史与温度/流量/压力子视图两个在线估计器，共享物理推进器并匹配双方未来状态。子视图不是独立物理真值，也没有新增特权传感器；称为交叉预测改造，不是原JEPA-x复现。
- 隐状态8维有固定温度坐标，其中五维在编码时直接等于观测温度，不使用任意投影以免产生表示塌缩捷径；不强迫未知金属温度具有虚构方差。辅助误差含观测温度再加权及未测金属状态一致性，不单独归因于因果辨识。
- 所有未来历史只用于训练目标。原11路旁路仅使用起点历史摘要，未来目标估计仍只获得起点旁路，不读取未来旁路。
- 连续物理状态跨块保留；本模型block接口与native为同一连续递推，分列为接口兼容，不能当作两个独立性能结果。

## 实现顺序

1. 保存focused回传表与观察；核对对齐响应及温度数组。
2. 新增physical_models.py及测试：验证离散热收支、无未来泄漏、动作前隔离、单纯混合极限、JEPA梯度路径。
3. 新增physical.py：三个拟合共六个checkpoint评价，复用调度/完整动作评价；保留失败、训练状态、原始输出与参数值。
4. 小数据全流程测试及既有回归测试，不在本地执行正式训练。
5. 推送代码、说明及Linux单命令；回传后先看P0能否保住精度，再判断P1/P2增量，不因latent loss低而放行。
