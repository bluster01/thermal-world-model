## 1. 数字不是误算，但解释需要收回到证据范围

同一验证窗口、equal-day H18 累计主汽温 MAE（°C）：

| 模型 | seed 0 | seed 1 | seed 2 | 均值 |
|---|---:|---:|---:|---:|
| GRU 融合 | 0.441414 | 0.421645 | 0.466357 | 0.443139 |
| Token 融合 | 0.708643 | 0.634020 | 0.620269 | 0.654311 |
| 持续值 | 0.638755 | 0.638755 | 0.638755 | 0.638755 |

Token 均值比持续值差 2.44%，比 GRU 差 47.65%；但不能说每个 seed 都不如持续值：
seed 1/2 略优于持续值，seed 0 显著更差。

六份保存预测的 MAE 已独立重算并与 report 对齐；checkpoint 哈希、observer 源码
哈希与 Linux 回传身份一致。六个 best_step 都等于 ledger 中主汽温 MAE 的最小点，
因此没有发现拿错最佳 checkpoint 或把 NLL 当成 MAE 的错误。
Token best_step 分别是 23800、23600、22000，三次均跑到 24000 cap；
预算用完不等于收敛。尾部日志仍有波动，仅凭此也不能指定延长训练就会解决。

冻结晋级规则下仍是 GRU 胜出；**当前数字只描述这次实现/训练的结果，不能作为 token
架构本质较差的可靠证据。** 数值可复核与模型训练健康是两个不同审计层次。

## 2. 已复现的异常：有界修正接近常量

源码 `src/final_wm/observer.py:217`：

`delta = 0.1 * state_scale * tanh(delta_raw)`

hybrid 只保留索引 3–6，即三个金属温度和燃烧偏移的初态修正。
对真实回传最佳 observer 权重，使用训练统计量构造两组、每组 32 个不同历史：
一组为逐点随机扰动，另一组为平滑偏移与斜坡。两组都不是现场验证历史。
在平滑组上，按修正上界归一化后：

| 观察器 | 四状态修正特征 | 跨历史标准差 | `tanh` 局部导数 |
|---|---|---|---|
| Token seed 0 | 约 `[+1,-1,-1,+1]` | 约 4e-8–8e-8 | 约 3e-7–1e-6 |
| Token seed 2 | 约 `[+1,-1,+1,-1]` | 约 1e-8–1e-7 | 约 1e-6–3e-6 |
| Token seed 1 | 四个状态都约 -0.92 | 约 0.006 | 约 0.14 |
| GRU 三种子 | 随不同历史显著变化 | 约 0.12–0.45 | 未出现上述全面饱和 |

seed 0/2 的 raw 输出绝对值约 7–8；相应四个修正几乎固定为各自正/负上界。
seed 1 不宜叫“饱和”：更准确是四个状态读出接近、历史区分较弱。
这给出了可复现的**观察器退化迹象**，并提供梯度经 tanh 被强烈压缩的机制。
不能据此断言所有真实窗口均退化，或量化它解释了多少 MAE 差距；需原验证历史前向确认。
更不能据此将动作响应较负自动等同于现场响应正确。

## 3. 对照旧实现与排除项

- Phase 1 `exp_025_unified_benchmark.py:100` 的 TimeXer/M9 使用 RevIN、主汽温
  patch、独立未来动作 cross-attention 和完整 patch flatten 温度预测头。
  同文件 `:337` 的 iTransformer 也是直接输出温度，而非物理状态修正。
- Phase 3.5 `src/phase35/multistep/rm3_prediction.py:168` 的 M9 使用时间 queries、
  独立未来 SP attention 和基准温度上的直接增量头；H60、目标与划分都不同。
  本轮未将旧表数字当作当前 H18 的可比基准，也没有重新认证所有历史实验。
- 当前 token 只替换“历史到初态”的观察器，不读取未来动作，不直接修正温度输出。
  23 变量各自 11 patches，共 253 tokens，经共享 memory、11 个物理状态 queries，
  最终只有 4 个状态进入初态。并非旧版优秀预测模型的直接融合复现。
- `observer.py:106` 不只改变 encoder：GRU 是 11 行独立线性读出；token 是各状态
  query **共享一个标量读出头**（包括共享压力系数）。这是一项明确设计差异，不是
  已证实的索引 bug；它与 query 区分能力/梯度耦合应列为首要待检机制。
- patch `transpose/unfold/flatten` 的变量和时间轴对应正确；96、16、8 恰好覆盖
  最后一个历史点，未发现遗漏尾部或未来泄漏。扩展变量只在 adapter 标准化一次，
  observer 对扩展的 loc=0、scale=1，未发现扩展被二次错误标准化。
- 两个融合模型采用相同训练窗口、batch 抽样、5 温度 NLL、Adam 0.001、裁剪 10。
  相同 seed 下，活动 transition/closure 初始化一致；不同 RNG 消耗导致的非 observer
  初始化差异只见于本次 oracle 路径不使用的 boundary 网络，不能据此归因性能差距。
- 原梯度测试先随机化 mean head，再验证扩展有梯度；训练 report 的 active parameters
  只统计 `grad is not None`。它们能验证接线，但**不能检测训练后饱和和有效梯度枯竭**。
