# 双侧响应实验：验收与执行说明（2026-09-23）

本地完成代码与验收，Linux 只执行训练、回传。**更新：seed11八臂已完整回传并验收，见 `BILATERAL_RETURN.md`。** 以下保留原实施口径，小检查分数不用于选择模型。依据 `docs/plans/2026-09-22-bilateral-response-training-spec.md`；此前全部黑箱/SSM/R4 基线结果继续保留，本轮八个拟合是针对双侧信息、监督与响应校准的新比较，不代表重跑所有历史模型。

## 回传验收结论

接受 `fc0f8b8` 的字段映射与全部 1/3 起点；修复单位换算精度后接受数据包。原 CSV 浮点换算与冻结 mmap 在阀位上最多差 5.96e−8，在蒸汽流量上最多差 6.10e−5 kg/s，温度一致。`canonicalize_bilateral.py` 用原 A/B mmap 替换核心字段，旧 A/辅助归一化不变，新增八个字段仍只用去重后的 train 历史行拟合。原回传可从 Git `9ab31ba` 恢复，新旧哈希都在数据 manifest 内。三个分区全部历史/未来的 A/B 核心字段已与原 mmap 逐位核对，差值为零；A 与旧基线包、九个辅助字段也逐位相同。窗口数仍为 **20371 / 128 / 256**，strict 子组仍为 **13473 / 70 / 174**。Linux 直接用已提交的包，无需重扫 CSV 或再次 canonicalize。

不接受 `9ab31ba` 的旧自然事件曲线作为校准依据：声称的 60s 实际用了 10s 差分，匹配特征混入动作后数据，对照片段的提取起点不对应匹配起点，重叠窗口还重复计算同一事件。本地重写为时间去重、真实 60s 检测、纯动作前特征、统一提取时钟；保留旧报告并标为被替代。

修正后有 742 个同阀至少间隔 1920s 的匹配事件（四阀 139/205/216/182）。开大阀后的 0–180s 喷前/喷后温差变化均值依次为 −0.807/−0.975/−0.254/−0.526°C；末级 180–1280s 则为 −0.465/+0.528/+0.031/+0.485°C。**局部方向有一致证据，末级幅度尚不能裁定。** 匹配前趋势仍不完全平衡，控制片段可以跨事件复用，60s 后还有其他动作，因此不把 742 当成独立随机干预，也不把这些均值作为监督标签或已识别物理增益。

修正事件报告：`results/action_predictor_bench_20260919/bilateral_events_reviewed_20260923/`。已保存原始四阀计划、A/B 十温度、匹配前趋势、实际及控制片段的负荷/煤量/流量、全部起点，允许回看混杂来源。

## 八个拟合，首轮全部跑

| 臂 | 具体改变 | 回答什么 |
|---|---|---|
| G2 | 固定旧 D 的背景和输运，只拟合通向 A 末级的两个增益 | 幅度弱是否主要在末端读出 |
| S0_A | A 单侧 SSM；已有 B 首末温历史 + 九辅助；未来本侧两阀 | A 对照 |
| S0_B | B 镜像 SSM；A 首末温历史 + 相同九辅助；未来本侧两阀 | B 对照；辅助控制点仍有侧别不对称 |
| S1 | S0_A 加完整 B 五温度/另两阀历史；未来仍只有 A 两阀 | 完整双侧历史是否有帮助 |
| S2 | 与 S1 同历史，增加另两阀未来计划 | 遗漏未来阀门共动的影响 |
| S3 | 与 S2 同信息，输出并监督 AB 十温度 | 联合监督及 AB 选模调度的影响 |
| R3 | 两条连续 R4 输运链、完整历史与七边界 | 物理响应结构对照 |
| P3 | S3 名义背景 + 可训练连续 R4 响应 | 是否能同时保精度和恢复幅度 |

G2 从旧 D seed11 出发，新增可训练参数恰好 2 个；它是有意的旧模型校准，不与新架构直接做纯结构归因。其余 S0–P3 从头训练。首轮种子 11；后续候选和直接对照再补 23/37，首轮不宣布跨种子胜出。

新 SSM 的核心：14 路本侧历史经 GRU 编码到 48 维；每个时间步以隐藏状态、本侧五温度、允许输入的未来阀位、七个外部边界计算状态更新，48 个可学习时间常数控制变化速度。小型历史适配器加入对侧与九辅助信息。S3 从同一隐藏状态多读出 B 五温度，native 中 B 预测不回写到 A 状态；S2/S3 的公共模块同种子初值完全一致。这个 SSM **没有单调性保证**，需要实测方向、幅度、时延和回弹。

R3/P3 的候选阀计划只进入对应输运链，参考背景由历史与共同边界驱动；P3 的名义 SSM 四阀固定在历史末点，不读候选计划。**更正：输运时间常数/增益还会读取响应状态，不是候选无关的系数；路径限制及正增益不保证任意候选对全程单调。** 也不能证明从观察数据识别了真实增益。P3 与 R3 的输运模块配对初始化。新的七边界全部使用；G2 延续旧 D 的六边界接口，是明确例外。少量反向及共同系数的零训练定位见回传报告。

## 预算与评价口径

- 同一 20371 train、128 selector、256 development evaluation 起点；历史 64、监督 128、推演 512 步，每步 10s。
- Adam，batch128，至少 12 / 最多 90 epoch，LR 1e−3→1e−4，selector 实质改善阈值 0.002°C；当前 LR 等 4 轮才下降，降至下限后等 6 轮再停。到 90 轮未到平台必须标为 `budget_limit`，不能说“已充分收敛”。
- 单侧归一化损失权重 `[.125,.125,.125,.125,.5]`，前32/后96各半；联合损失 **LA+LB**。联合臂同时保存 A short/balanced 与 AB short/balanced；LR/停训看 AB 对，故 S2→S3 包含联合监督与选模调度两个变化。
- native 连续推演；block_context_fixed 每32步重编码自身预测，对侧历史固定；block_joint_refresh 允许 AB 自己的预测更新历史，九辅助始终固定原历史，绝不回填真实未来温度。联合臂的 context_fixed 只报告 A。R3 三种模式实际相同，明确标记为别名，不能当成重复证据。
- 所有 checkpoint 保存预测数组和 H32/H128/H512、129–512尾段、每128步块、逐温度/逐侧 MAE、60s变化误差；含加/减负荷、波动/稳定、反向负荷、训练支持范围内/外、strict与近关阀子组。支持范围外是以 train 起点特征1%/99%分位定义的外推子组，不是新的独立外部数据。
- 部署 selector（单侧 balanced、联合 AB_balanced）及固定旧 D 保存完整响应：四阀、±1/3/5pp、阶跃/斜坡/正弦/平滑/短脉冲/双脉冲，窗口前/中/后及块边界两侧，双阀同反向，记录/固定边界与其他阀。同起点 H512 与 H128 前缀均保留；比较剂量只用共同合法起点。原始负反馈保留，越界剔除并保存 mask，不偷偷裁剪。
- 双侧输出保存全部 4×10 路径；单侧缺少的输入/输出标 N/A，不能以零响应算成功。P3 两种模式的响应是数学上同一个连续输运差值，直接标为相同。峰谷、时刻、面积、尾值、恢复、反向均保留，不用最深谷底当训练目标。
- 部署模型还对上述真实 train 事件预测，并将目标阀单独固定在动作前端点，保存配对模型差值和匹配观察差值。这里不输出“因果 MAE”；两类差值不是同一种真值。

完整代码/数据/父权重/事件包/负荷上下文 SHA 与环境版本写入 config。断点保存模型、Adam、RNG、选模与停止状态；改变协议或源码将拒绝继续旧目录。只允许提高最大轮数。resume 不重复已完成且未更新 checkpoint 的评价。

## 本地验证范围

56 项测试通过：覆盖八臂前后段梯度、G2 仅两参数、缺失未来阀位/真实未来温度隔离、S2/S3 配对初始化、P3 背景隔离与路径、四个关键臂完整训练与断点恢复的权重/Adam/选模状态逐位一致，以及旧 runner 回归。另完成八臂各 4 个训练窗口、1 epoch 的端到端小检查，产生 22 个选模 checkpoint 加固定 D 的全部评价出口，完成后 resume 未重复拟合。

S3/R3/P3 的正式响应目录也在 2 个起点上完整跑过：272/136/272 个“动作×模式×边界方案”，动作前响应全部为零，合法起点结果有限。这里验证的是代码，不是训练效果。固定 D 包装在 3 个 H512 起点上与原实现的 float64 结果逐位相同；float32 最大差异为 native 0.000061°C、block 0.000244°C，因此不声称 float32 预测逐位相同。`bilateral_verification_20260923.json`、`bilateral_acceptance_20260923.json` 和 `bilateral_fixed_D_reproduction_20260923.json` 保存具体证据。CUDA 和正式长训练由 Linux 执行后验收。

## Linux 命令

在现有 Linux 仓库、已有 PyTorch 环境中执行：

```bash
git pull --ff-only origin codex/action-predictor-bench
bash experiments/action_predictor_bench_20260919/run_bilateral_linux.sh
```

默认 CPU 单线程。若使用现成 CUDA 环境，可在第二行前加 `DEVICE=cuda`；整轮配对臂统一设备与 batch。若需脱离终端：

```bash
nohup bash experiments/action_predictor_bench_20260919/run_bilateral_linux.sh > bilateral33_seed11.log 2>&1 &
```

中断后重跑同一条命令即可。不要重建数据、改实现、减少臂或截短预算。某一臂失败会保留 traceback 并继续其余臂，最后返回非零；失败应回传本地修复。

输出默认 `results/action_predictor_bench_20260919/bilateral33_seed11/`。回传整个目录，包含 config/state、fits 下全部 best/last 和 training.jsonl、各 selector 的 predictions、部署模型 responses / natural_events 数组及对应 JSON；不要只回传排名表。仓库忽略 pt/npz，回传时需显式加入整个指定目录：

```bash
git add -f results/action_predictor_bench_20260919/bilateral33_seed11
git commit -m "Return bilateral seed11 full-budget fits and response evaluation"
git push origin codex/action-predictor-bench
```

正式结果回传后，先看精度是否有损失，再看响应恢复在哪里。任何 MAE 上升都报告；2%工程容忍度不能改称“零损失”。达到方向约束也不能改称“真实物理幅度已经解决”。
